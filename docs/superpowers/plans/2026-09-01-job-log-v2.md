# Pegel Job Log v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Pegel's private local decision file into a durable application timeline without changing the search API, sending candidate data to Pegel, or losing schema v1 state.

**Architecture:** Keep one standard-library Python JSON store. `job_decisions.py` owns schema validation, v1 normalization, event ordering, locking, backups, and atomic writes. `pegel_query.py` owns argument validation, the optional public snapshot read, safe text rendering, and stable JSON envelopes. Every mutation holds a non-blocking advisory lock across read, migration, and write.

**Tech Stack:** Python 3.11 standard library, pytest, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-09-01-job-log-v2-design.md`

## Global constraints

- Preserve the current state path and `PEGEL_DECISIONS_FILE` override.
- Add no Python dependency.
- Never put a status, note, reason, contact, or date in a Pegel request.
- Record only an explicit candidate statement. `passed` always means "chose not to pursue."
- Search excludes every job ID present in the log unless `--include-decided` is set.
- Read-only access to schema v1 must not change either the source file or create a backup.
- The first successful schema v1 mutation must preserve the exact original bytes beside the source.
- Keep the search JSON envelope byte-shape compatible at its top level.
- Run each named RED command before changing production code and confirm the asserted behavior fails for the expected reason.

## Task 2: Make migration and concurrent writes loss-resistant

**Files:**

- Modify: `evals/test_job_decisions.py`
- Modify: `scripts/job_decisions.py`

- [ ] **Step 1: Add exact schema v1 migration-backup tests.**

  Exercise the first `record_decision` mutation of a v1 file and assert:

  - `job-decisions.json.v1.bak` is byte-for-byte identical to the original;
  - the source is valid v2 with the v1 event followed by the new event;
  - a matching pre-existing backup is accepted;
  - a different pre-existing backup raises `DecisionStoreError` and leaves source and backup unchanged;
  - read-only list/history never create a backup;
  - on POSIX, a newly created backup and source are mode `0600`.

- [ ] **Step 2: Add lock contention and I/O failure tests.**

  Use the production lock context manager to hold the lock, then call a second mutation and require a concise busy error. Monkeypatch one filesystem boundary at a time for backup creation, temporary write, chmod, and replace. For each failure, assert the original source bytes remain intact and no traceback escapes as raw `OSError`.

  Permission assertions must be guarded with `if os.name != "nt"`; Windows must still execute migration, replace, and lock-contention behavior.

- [ ] **Step 3: Run the RED durability slice.**

  Run: `python3 -m pytest evals/test_job_decisions.py -q -k 'migration or backup or lock or failure or permission'`

  Expected: missing backup/lock behavior and raw `OSError` failures.

- [ ] **Step 4: Implement one lock around every read-modify-write transaction.**

  Add `_store_lock(path)` as a context manager. Its reusable lock path is `Path(f"{path}.lock")`; it sits beside the state file, contains no candidate data, and uses non-blocking acquisition:

  - Unix: `fcntl.flock(fd, LOCK_EX | LOCK_NB)`;
  - Windows: ensure one byte exists, seek to byte zero, then `msvcrt.locking(fd, LK_NBLCK, 1)`;
  - acquisition conflict: raise `DecisionStoreError("Decision file is busy; retry the command")`;
  - release in `finally`, keeping the reusable lock file in place.

  `record_decision` and a successful `forget_decision` must read, normalize, and write while holding the lock. A no-op forget may return `False` without rewriting the file, but it must still make its existence decision under the lock.

- [ ] **Step 5: Implement exact backup and atomic replace boundaries.**

  Split the write path into narrowly named helpers:

  - `_read_store(path)` returns normalized v2 state, original schema version, and exact source bytes;
  - `_ensure_v1_backup(path, source_bytes)` creates `Path(f"{path}.v1.bak")` exclusively with mode `0600`, or verifies exact equality;
  - `_atomic_write(path, store)` writes UTF-8 JSON plus a final newline to a private temporary file, flushes and `fsync`s it, then calls `os.replace`.

  Catch `OSError`, `UnicodeError`, and serialization boundary errors at the helper edge and re-raise a concise `DecisionStoreError` with the path. Remove only a temporary or partial backup created by the current attempt. Never remove a pre-existing backup.

- [ ] **Step 6: Run durability and full persistence tests GREEN.**

  Run: `python3 -m pytest evals/test_job_decisions.py -q`

  Expected: all schema, migration, permission, failure, and contention tests pass with no skips on the current platform.

- [ ] **Step 7: Commit durability.**

  ```bash

  git commit -m "feat: safeguard local job log writes"
  ```
